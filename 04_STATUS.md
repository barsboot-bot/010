## 2. Что проверено автоматически

`python tools/check_project.py`:

* баланс скобок во всех `.c` (с корректным разбором строк и комментариев);
* дубли классов между модами;
* нарушения слоёв (`3_Game` не ссылается на `4_World`/`5_Mission`) — этот чек
  поймал 2 реальные ошибки в процессе разработки (`PlayerBase` из `3_Game`,
  `MR_ClientRPC` из `3_Game`), они исправлены;
* вызовы несуществующих методов у классов `MR_*`;
* `ref EffectSound` (источник крашей);
* контракт `index.json` ↔ `config.cpp` ↔ `.ogg` файлы;
* что каждый виджет, который ищет `MR_RadioMenu.c`, есть в `.layout`;
* наличие обязательных папок воркшоп-структуры;
* текстуры: каждый `.rvmat` ссылается на три `.paa` по правильному пути, и под
  каждую ссылку существует исходный PNG в `Models/tex_src/`; PNG в PBO не
  попадают (в staging только `.rvmat`).

`python tools/generate_db_config.py` прогнан на демо-данных: генерирует
`CfgSoundShaders`/`CfgSoundSets` с правильной формулой имён, обновляет
`index.json`, пишет отчёт об отсутствующих файлах.

Результат на текущем дереве: `OK - no errors, 4 warning(s)` (все четыре — «класс наследует model у родителя», это норма).

## 3. Что проверить на Windows (обязательный чек-лист)

Это не «может быть», а «надо сделать один раз перед публикацией». Каждый пункт —
место, где движок может повести себя иначе, чем в документации.

1. **Компиляция** — запустить сервер с тремя модами и посмотреть `script.log`:
   ищем `[MusicRadio] Server engine ready`, ошибок компиляции быть не должно.
   Если что-то не скомпилируется, вероятные места:
   * `MR_VehicleRadio.HasRadioInCargo` — `GameInventory.GetCargo()`;
   * `MR_WorldHooks` — `GetHierarchyRoot()`;
   * `MR_ServerEngine` — `GetInventory().HasEntityInInventory()`.
2. **UI** — F7 в машине: меню должно открыться и не «проваливаться» сквозь
   другие меню; слайдеры и вкладки реагируют.
3. **Звук** — трек играет, громкость меняется, на 100 м не слышно, на 20 м
   слышно; в чате появляется «Now playing: ...».
4. **Опоздавший игрок** — зайти вторым в радиус: должен услышать с той же секунды.
5. **Отказ** — попробовать включить музыку без рации в грузе: сервер должен
   ответить текстом, а не тишиной.
6. **Рестарт** — сессии не должны «воскресать» после перезапуска сервера
   (музыка начинается заново только по новой команде игрока).
7. **Автопереход** — после конца трека включается следующий из той же
   категории; при `autoplayNext: false` радио замолкает.
8. **Носители** — заспавнить `MR_CassettePlayer`, вставить `BatteryD`,
   `MR_MemoryCard_01`, `MR_Cassette_Rock01`, нажать PLAY: должен заиграть
   альбом `rock01`, а NEXT должен идти внутри альбома. Без карты плеер должен
   отвечать `no memory card`.

## 4. Известные ограничения (осознанные)

| Ограничение | Почему так |
|-------------|------------|
| Только локальные `.ogg`, никакого эфира | интернет-радио снято с проекта: см. `_archive/internet_radio/` |
| `IsAdmin()` всегда `false` | в DayZ нет переносимой проверки прав для скрипта; расширяется одной функцией |
| Сессии не переживают рестарт | иначе машины на карте пели бы вечно |
| Только `.ogg` | другие форматы движок не проигрывает |
| Один трек на один объект-хост | одна машина = один стерео-источник, как в жизни |

## 5. Что стоит сделать дальше (не входит в текущий объём)

1. **Действие в меню предмета** (`AddAction` на `PersonalRadio` и на машине),
   чтобы не только F7, но и привычное контекстное меню.
2. **Сохранение плейлистов** в `$profile:MusicRadio/playlists/`.
3. **Плейлисты по жанрам** с иконками (сейчас — вкладки «MUSIC» / «ALL TRACKS»).
4. **Права через мод прав** (CF/Expansion) — одна функция `IsAdmin`.
5. **Метка «сейчас играет» на HUD** (небольшой виджет в углу).
6. **Затухание по стенам** — через `occlusionFactor`, уже частично настроено.

## 6. Сборка и публикация

```bash
python tools/check_project.py        # должно быть: OK - no errors
python tools/generate_db_config.py   # пересобрать базу после добавления музыки
python tools/stage_pbo.py --clean    # staging для PBO, должно быть problems: 0
BUILD_PBO.bat                          # PBO + подпись (Windows)
```

Далее: `@MusicRadioCore` и `@MusicRadioDB` — в Workshop, `@MusicRadioServer` —
только на сервер (можно держать приватно).
