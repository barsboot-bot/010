# Как в игре проверить музыку (пошагово)

Всё, что нужно, есть в текущей сборке: два трека в демо-альбоме `Demo Rock A`.
Проверка идёт через **наушники/колонку рядом с игроком** — музыка позиционная,
её слышит тот, кто стоит рядом с источником.

---

## 0. Перед запуском — три вещи, без которых ничего не заиграет

| что | как проверить |
|---|---|
| **AudioConfig на сервере** | должен лежать `mpmissions\<карта>\MusicRadio\AudioConfig.json`. Если нет — мод создаёт его сам из `server_files\profiles\MusicRadio\AudioConfig.json` |
| **типы предметов в миссии** | блоки из `server_files\mpmissions\types_musicradio.xml` должны быть в `types.xml` миссии (иначе предметов не будет ни в луте, ни в админ-спавне) |
| **треки реально в базе** | `@MusicRadioDB\Music\Rock\demo_track_01.ogg` и `demo_track_02.ogg` (в PBO они уже упакованы) |

Быстрая проверка на стороне сервера:

```
python tools\check_pbo.py            # в PBO лежат скрипты и config.cpp
python tools\check_fresh.py          # на сервере именно эта сборка
```

---

## 1. Что заспавнить (админ-спавн, ESC → админ-панель → Spawn)

| предмет | класс | зачем |
|---|---|---|
| кассетный плеер | `MR_CassettePlayer` или `MR_CassettePlayer_Black` | сам плеер (дека) |
| кассета с альбомом | `MR_Cassette_Rock01` | «Demo Rock A», 2 трека |
| карта памяти | `MR_MemoryCard_01` | обязательна, вставляется В КАССЕТУ |
| батарейка | **D-батарейка** (ванильная `BatteryD`) | обязательно, в слот батареи плеера (`attachments[]` плеера) |

Мини-диск-вариант: `MR_MiniDiscPlayer` + `MR_MiniDisc_Rock01` + те же карта и батарейка.

---

## 2. Собрать плеер (это главное — без всех трёх вложений музыка не заиграет)

С 20261172 **карта памяти вставляется в саму кассету** (как в реальности:
кассета = носитель, карта хранит данные). Порядок:

1. **в кассету**: открыть инвентарь → перетащить `MR_MemoryCard_01` в слот
   `MR_MemoryCard` кассеты `MR_Cassette_Rock01`;
2. **в плеер**: перетащить кассету в слот `Cassette`;
3. **в плеер**: вставить батарейку (слот `BatteryD`).

Для мини-диска — то же самое, только карта вставляется в `MR_MiniDisc_Rock01`,
а он сам — в `MR_MiniDiscPlayer`.

На модели плеера видно слоты так же, как на скриншоте: `Cassette` (носитель) и
`BATTERY`. Раньше карту было физически некуда вставить — у кассеты не было
слота, и плеер навсегда отвечал `"no memory card"` (ревизия 20261172 это
исправила).

Если чего-то не хватает, меню так и скажет: `"no 9V battery"`,
`"no memory card"`, `"no carrier"` — это тексты из `MR_IsReady()` (`MR_Decks.c`).

## 3. Открыть меню и включить

| действие | клавиша |
|---|---|
| открыть радио-меню | **F7** |
| остановить воспроизведение | **F8** |
| закрыть меню | **F7** ещё раз или **ESC** |

F7 работает в двух случаях:

* **плеер/кассета в руках** — меню привяжется к этому предмету;
* **сидите в машине** — меню привяжется к машине (см. шаг 5).

Если ничего не подходит, в чат придёт: `[Radio] get in a vehicle or hold a radio`.

В меню:

1. вкладка **TAPES** (третья: `MUSIC` / `ALL TRACKS` / `TAPES`) → выбрать кассету из списка (список строится из манифеста, который присылает сервер);
2. нажать **PLAY** (для кассеты кнопка подписана `PLAY TAPE` — играет всю сторону с повтором);
3. внизу видно `Library: N tracks` и текущий трек; **следующий трек запустится сам** (так задумано для кассеты).

Ожидаемый результат: в правом верхнем углу меню — название трека, звук идёт из плеера,
слышно в радиусе ~40 м (по умолчанию).

---

## 4. Что должно появиться в логах (проверка, что RPC ходят)

Сервер (`-dologs`, файл `script_*.log` или `*.RPT`), искать `[MusicRadio]`:

```
[MusicRadio] Client mission ready
[MusicRadio] Config received from server (v1)
[MusicRadio] request from <ваш ник>: action=1 track=...      <- запрос библиотеки
[MusicRadio] request from <ваш ник>: action=2 track=rock01   <- нажали PLAY
```

`logRequests` в `AudioConfig.json` включает эти строки (по умолчанию `true`).

Полезные строки на клиенте:

| строка | что значит |
|---|---|
| `Client audio manager started` | инициализация прошла |
| `PLAY: host not in this client's bubble, ignored` | сервер прислал PLAY, но объект далеко — подойдите ближе |
| `PLAY for unknown track id: …` | сервер и клиент разошлись по базе (разные версии `@MusicRadioDB`) |
| `Cannot create UI from MusicRadioCore/gui/layouts/radio_ui.layout` | не тот PBO/битый архив |

Если в логе **нет** ни одной строки `[MusicRadio]` — скрипты не загрузились
(не тот мод-лист), а не «музыка не работает».

## 4b. Проверка «музыка из рации» (с 20261174)

Рация перестала играть «из воздуха»: с 20261174 она такой же плеер, как дека —
играет **только вставленную** кассету/диск, и только с картой памяти и
батарейкой.

Порядок:

1. заспавнить `PersonalRadio` + `BatteryD` (ванильная D-батарейка) +
   `MR_Cassette_Rock01` + `MR_MemoryCard_01`;
2. карту `MR_MemoryCard_01` → **в кассету** (у кассеты свой слот, см. шаг 2);
3. кассету → **в рацию** (слот «Music media» в инвентаре рации);
4. `BatteryD` → в рацию (слот `BATTERY`);
5. взять рацию в руки, нажать **F7** → вкладка **TAPES** покажет альбом из
   рации, **PLAY TAPE** — заиграет.

Если чего-то не хватает, в чат придёт точная причина:

| сообщение | чего не хватает |
|---|---|
| `The radio is not ready: no cassette or disc inserted` | нет кассеты/диска в рации |
| `The radio is not ready: no memory card` | нет карты в кассете |
| `The radio has no working battery` | нет `BatteryD` |
| `docked cassette: album 'rock01'` | всё на месте (это ответ машины) |

Вернуть старое поведение (рация играет любой трек без носителя) можно флагом
`"radioNeedsCarrier": false` в `mpmissions\<карта>\MusicRadio\AudioConfig.json`.

## 5. Проверка «музыка в машине» (кассета в машине, с 20261173)

Слот для машины называется **`MR_DashSlot`** и объявлен в `CfgSlots`
(`@MusicRadioCore/config.cpp`). Класть в него можно **кассету, мини-диск или
целый плеер** — играет то, что положили.

Порядок проверки:

1. сесть в машину (слот виден в инвентаре машины, раздел «RADIO AND PLATE»);
2. в слот положить кассету `MR_Cassette_Rock01` (или плеер с вставленной
   кассетой и батарейкой);
3. нажать **F7** — меню привяжется к машине; в чат придёт
   `docked cassette: album 'rock01'` или `docked deck: album 'rock01'`;
4. выбрать трек и **PLAY**.

Если в чат пришло `no deck docked (use a cassette or a player in the dash
slot)` — слот пуст. Если `The radio's battery is empty` — сработало правило
`requireRadioItemInCargo: true` и в багажнике лежит рация без батарейки; с
занятым слотом правило уже не применяется.

**Чего ждать НЕ надо:** предмет в слоте не рисуется на торпеде. Для этого
нужна селекция `MR_DashSlot` в `.p3d` машины и прокси-модель —
`docs/07_MODELS.md`, п. 6. Вставить, вынуть и слушать — работает.

Обходной путь без слота (работает всегда): `"requireRadioItemInCargo": false`
в `mpmissions\<карта>\MusicRadio\AudioConfig.json` — тогда достаточно сесть
за руль и нажать F7.

## 6. Быстрый чек-лист, если тишина

| симптом | где смотреть | что делать |
|---|---|---|
| F7 ничего не делает | чат | в чате будет причина (`get in a vehicle or hold a radio`, `radio battery is empty`) |
| меню открылось, список пуст | лог клиента | нет манифеста: проверьте `request from … action=1` на сервере (RPC не дошли) |
| трек нажимается, звука нет | `MR_ClientAudio` в логе | трек помечен `pack missing` — не совпали версии `@MusicRadioDB` у клиента и сервера |
| «PLAY, но тишина» у другого игрока | позиция | музыка слышна в радиусе; проверьте `defaultRadius` в `AudioConfig.json` |
| меню не открывается совсем | `script_*.log` | `MR_MenuEvents`/`UIScriptedMenu` — пришлите лог |

---

## 7. Одна фраза для проверки «жив ли мод вообще»

Заспавнить `MR_CassettePlayer` + `MR_Cassette_Rock01` + `MR_MemoryCard_01` + `BatteryD`,
собрать (карта → в кассету, кассета → в плеер, батарейка → в плеер), нажать **F7**,
вкладка **TAPES**, **PLAY TAPE**. Если заиграло — вся
цепочка (скрипты → RPC → сервер → база → звук) работает.
