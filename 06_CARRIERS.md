# Носители музыки: карта памяти, кассета, MD

Документ про физическую часть мода: что игрок держит в руках, что вставляет в
устройство и как это связано с аудио.

## 1. Главное правило

**Один носитель = один альбом. В носителе нет аудио.**

Кассета `MR_Cassette_Rock01` — это только класс предмета и ключ `rock01`.
Звук лежит в медиа-паке (`@MusicRadioDB`, `CfgSoundSets`) и подтягивается по
обычному контракту `provider|trackId`. Поэтому:

* кассета не увеличивает папку DayZ ни на байт;
* новую кассету добавляет json + три строки в `config.cpp` (и то и другое —
  без пересборки аудио);
* «нашёл кассету с альбомом» — это про лут и торговлю, а не про скачивание.

## 2. Предметы

| Класс | Что это | Слот | Вес | Где взять |
|-------|---------|------|-----|-----------|
| `MR_MemoryCard_01` | карта памяти для рации / плеера | `MR_MemoryCard` | 10 г | лут, Town/Village/Office/School |
| `MR_CassettePlayer` / `_Black` | кассетный плеер (дека) | 2×2 в инвентаре | 550 г | лут, Town/Village |
| `MR_MiniDiscPlayer` | MD-плеер | 2×2 | 400 г | лут, Town/Office |
| `MR_Cassette_Rock01` | кассета с альбомом `rock01` | `MR_Cassette` | 40 г | лут, Town/Village |
| `MR_MiniDisc_Rock01` | MD с тем же альбомом | `MR_MiniDisc` | 30 г | лут, Town/Office |

Базовые классы (`*_Base`, `scope = 0`) не спавнятся и не вставляются — это
заготовки, из которых делаются альбомные варианты.

**Модели пока ванильные** (`WalkieTalkie.p3d`, `BoxOfMatches.p3d`,
`Compass.p3d`, `sewing_kit.p3d`): мод работает без своего арта, а когда
появятся ваши `.p3d`, меняется только строка `model = ...`. Классы при этом
не переименовываются.

## 3. Что нужно плееру

Кассетная дека и MD-плеер требуют три вещи (`MR_IsReady()`):

1. **9V батарейку** — слот `BatteryD` (ванильный);
2. **карту памяти** — слот `MR_MemoryCard`;
3. **кассету или диск** — слот `MR_Cassette` / `MR_MiniDisc`.

Рация (ванильный `PersonalRadio`) получила дополнительно слот карты памяти:
`MR_GetMemoryCard()`, `MR_HasMemoryCard()`, `MR_CardHint()`. Русская логика
осталась прежней: карта — «ключ», музыка на ней не хранится.

**Игровое следствие, которое вы просили:** без карты нечего играть. Плеер без
карты отвечает `no memory card`, сервер такой запрос отклоняет.

## 4. Как это играется

```
взять кассетный плеер
вставить BatteryD
вставить MR_MemoryCard_01
вставить MR_Cassette_Rock01
нажать "PLAY" (или MMB по треку) -> сервер читает, что вставлено
                                    -> AlbumOf("MR_Cassette_Rock01") = "rock01"
                                    -> играет первый трек альбома
дальше автопереход идёт ТОЛЬКО внутри альбома и по кругу (как плёнка)
```

Сервер **не верит** id, который прислал клиент: он смотрит на вставленный
предмет и сам выводит альбом из имени класса. Хакер с поддельным пакетом
получит максимум тот альбом, который физически лежит в его деке.

## 5. Как добавить новый альбом (1 шаг)

```bat
tools\import_music.bat        REM перетащить папку с альбомом
```

Импортёр сам создаёт **оба** носителя альбома и прописывает их везде, где нужно:

| Что генерируется | Где | Зачем |
|------------------|-----|-------|
| `MR_Cassette_<Альбом>` | `@MusicRadioDB/config.cpp`, между `@@CARRIER_CLASSES@@` | кассета, слот `MR_Cassette` |
| `MR_MiniDisc_<Альбом>` | там же | MD, слот `MR_MiniDisc` |
| оба класса в `types.xml`-сниппете | `server_files/mpmissions/types_musicradio.xml` | без записи в types предмет **никогда не заспавнится** |
| оба класса в `cfgspawnabletypes.xml` | `server_files/mpmissions/cfgspawnabletypes.xml` | плеер в луте иногда появляется уже с кассетой/диском |

Аудио в носителе по-прежнему нет: класс — это ключ альбома
(`MR_MiniDisc_Kostya` → `kostya`), звук берётся из медиа-пака.

**Как получить MD в игре.** Три способа, все рабочие:

1. **Лут:** `MR_MiniDiscPlayer` спавнится с шансом 50 % уже с диском внутри
   (шанс 0.20 для нового альбома, 0.40 для демо-альбома — правится в
   `cfgspawnabletypes.xml`).
2. **Админ-спавн:** `#spawnitem MR_MiniDisc_Kostya` — предмет есть в types.
3. **Своими руками:** найти `MR_MiniDisc_Kostya` в луте (nominal 4 на карте,
   тиры Tier2–Tier3) и вставить в `MR_MiniDiscPlayer` (слот `MR_MiniDisc`).

Кассета работает точно так же: `MR_Cassette_Kostya` + `MR_CassettePlayer`.

Проверить, что оба носителя «привязаны»:

```bash
python tools/check_project.py
# чекер сравнивает carriers.json с types-файлами и падает, если для альбома
# нет кассеты или MD:
#   ERROR 'MR_MiniDisc_Kostya' (album 'kostya') is not in types.xml or
#         types_musicradio.xml - the item would never spawn
```

## 6. Лут

`server_files/mpmissions/types.xml` — **ваш** файл с уже вписанными шестью
записями (в начале, между маркерами `MusicRadio: carriers`). Остальные 1941
запись не тронуты, порядок и атрибуты сохранены.

`server_files/mpmissions/cfgspawnabletypes.xml` — необязательный сниппет: с
ним заспавненная дека иногда приходит с батарейкой, картой и кассетой. Если у
вашей миссии такой файл уже есть — копируйте только блоки `<type>`.

Проверка: чекер сверяет, что все `MR_*` в этих файлах существуют в
`config.cpp`, чтобы опечатка не давала «тихий» пустой лут.

## 7. Что это НЕ делает

* не хранит и не передаёт аудио (иначе пак вырос бы ровно на размер музыки);
* не даёт «одна кассета — много альбомов» (сознательно: один носитель = один
  альбом);
* не требует своего арта, но и не выглядит как настоящая кассета, пока модели
  не будут нарисованы.
