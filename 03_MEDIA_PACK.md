# Медиа-пак: как добавлять музыку

Третий мод (`@MusicRadioDB`) — единственное место, где лежит музыка. Он будет
постоянно расти, поэтому всё, что нужно для добавления трека — это файл и одна
строка в json. Код первых двух модов при этом не меняется.

## 1. Структура пака

```
@MusicRadioDB/
├── config.cpp                    <- генерируется, не править руками
├── Music/
│   ├── index.json                <- генерируется (слитый каталог)
│   ├── Rock/
│   │   ├── playlist.json         <- вы её пишете
│   │   ├── track_01.ogg
│   │   └── track_02.ogg
│   ├── Chill/
│   │   └── ...
│   └── DatabaseConfig.json       <- провайдеры пака
└── Scripts/4_World/MR_DB_Placeholder.c
```

Правила:

* **только `.ogg` (Ogg Vorbis)** — другие форматы движок не проигрывает;
  конвертация: `ffmpeg -i in.mp3 -ac 1 -ar 44100 -c:a libvorbis -q:a 5 out.ogg`;
* **моно** для 3D-звука (стерео в `spatial = 1` может вести себя странно);
  для «наушников» (`broadcastToOthers: false`) стерео допустимо, но проще
  везде моно;
* имена файлов — латиница/цифры/`_` (пути попадают в PBO и в SoundSet);
* 1 песня ≈ 1–3 МБ при `-q:a 5`; 500 треков ≈ 1 ГБ — распределяйте пак по
  жанровым PBO при необходимости.

## 2. Формат playlist.json

```json
{
  // провайдер: должен совпадать с provider в индексе
  "provider": "MusicRadioDB",
  "tracks": [
    {
      "id": "rock_track_01",            // уникальный, [a-z0-9_] — попадёт в имя SoundSet
      "kind": "music",                  // music | radio | sfx
      "title": "Название",
      "artist": "Исполнитель",
      "album": "Альбом",
      "year": 2026,
      "duration": "3:42",               // или секунды числом; можно опустить (ffprobe)
      "tags": [ "rock", "night" ],
      "file": "Music/Rock/rock_track_01.ogg",
      "volume": 0.85,                   // базовая громкость сэмпла 0..1
      "enabled": true,
      "explicit": false,                // true = скрыт, если сервер запретил
      "loop": false
    }
  ]
}
```

Что можно не заполнять: `duration` (подставит `ffprobe`, если установлен),
`year`, `album`, `tags`. Что обязательно: `id` и `file`.

Допускается «словарная» форма вместо массива — удобно для ручного ведения:

```json
"tracks": {
  "1": { "id": "rock_track_01", ... },
  "2": { "id": "rock_track_02", ... }
}
```

Комментарии `//` и `#`, висячие запятые и одинарные кавычки разрешены — парсер
в моде (`MR_Json`) к ним терпим, и генератор тоже.

## 2.1 Альбомы и носители (кассеты / MD)

**Один носитель = один альбом.** Кассета или MD — это только «какой альбом
играть»; аудио в них не лежит, оно остаётся в медиа-паке. Такая кассета весит
40 г инвентаря и ноль байт в паке.

У каждого трека обязателен `albumId` — по нему трек привязывается к носителю:

```json
{
  "id": "demo_track_01",
  "album": "Demo Rock A",      // как альбом называется для игрока
  "albumId": "rock01",         // ключ: из него делается класс кассеты
  "file": "Music/Rock/demo_track_01.ogg"
}
```

Если `albumId` не указан, генератор берёт `album` (в нижнем регистре) или имя
папки, и пишет об этом в отчёт. Дальше `python tools/generate_db_config.py`
создаёт `Music/carriers.json` — список альбомов и нужных им классов предметов:

```
  albums          : 1
    rock01             2 track(s)   item: MR_Cassette_Rock01
  carriers.json written (1 album(s))
```

Класс предмета (`MR_Cassette_Rock01` / `MR_MiniDisc_Rock01`) живёт в
`@MusicRadioDB/config.cpp`, между маркерами `@@CARRIER_CLASSES_BEGIN@@` и
`@@CARRIER_CLASSES_END@@` (**в моде базы, не в Core** — добавили альбом,
пересобирается только DB) — **генератор пишет его сам**, руками туда лезть не
нужно и нельзя: имя класса и есть ключ альбома, опечатка = альбом, который
никто не сможет включить. Чекер `tools/check_project.py` ругается, если альбом
есть, а класса нет.

## 2.2 Добавить альбом за один шаг (Windows): `tools\import_music.bat`

Самый быстрый путь — не писать json руками, а дать скрипту папку с треками
(в любом формате):

1. Нужны **Python 3.8+** и **ffmpeg**. Батник сам их ищет и предлагает поставить
   через `winget`, если не нашёл; вручную — так:

   * Python: https://www.python.org/downloads/ — при установке обязательно
     галочка **«Add python.exe to PATH»**.
   * ffmpeg: https://www.gyan.dev/ffmpeg/builds/ (*release essentials*) —
     распаковать и положить `ffmpeg.exe` + `ffprobe.exe` в `tools\ffmpeg\`
     (или добавить в `PATH`).

   **Если в консоли `[WARN] ffmpeg not found` или ошибка `code 9009`:** это значит,
   что `python` в PATH — не Python, а заглушка Microsoft Store
   (`...\WindowsApps\python.exe`). Лечится так:

   * `Параметры → Приложения → Дополнительные параметры приложений →
     Псевдонимы выполнения приложений` → выключить `python.exe` и `python3.exe`;
   * либо поставить настоящий Python: `winget install -e --id Python.Python.3.12`,
     затем **закрыть и открыть консоль заново** (PATH читается при старте).

   Актуальная версия батника такие заглушки пропускает сама и ищет настоящий
   Python (`py -3`, `%LOCALAPPDATA%\Programs\Python\...`, `C:\Python3*`).
2. **Перетащить папку с альбомом на `tools\import_music.bat`** (или запустить
   файл и вставить путь).
3. Ответить на вопросы (все — по-русски, Enter оставляет значение в скобках):
   `Название альбома [имя папки]` → `Папка жанра [Rock]` →
   `Исполнитель для всех треков [из тегов]` → `Импортировать? [Y/n]`.

Что скрипт сделает сам:

| Шаг | Результат |
|-----|-----------|
| конвертация | каждый трек → Ogg Vorbis 44.1 кГц стерео, `-q:a 5` (≈160 kbps) |
| имена | `01 - Song.mp3` → `@MusicRadioDB/Music/<Жанр>/<albumId>_01.ogg` (порядок по номерам сохраняется) |
| теги | название и исполнитель берутся из тегов файла, если не заданы вручную |
| playlist | `@MusicRadioDB/Music/<Жанр>/<albumId>.json` (перезапись этого альбома, чужие альбомы в том же файле сохраняются) |
| база | `generate_db_config.py` → `config.cpp`, `index.json`, `carriers.json`, `types_musicradio.xml`, классы носителей |

То же самое из консоли (Linux/macOS/Windows), если батник не нужен:

```bash
python tools/import_music.py --source "D:\Music\Album" --album "Rock 01" --genre Rock
python tools/import_music.py --source ./album --album "Rock 01" --dry-run   # показать, не писать
python tools/import_music.py --source ./album --album "Rock 01" --no-convert # уже .ogg
```

Полезные ключи: `--artist "..."`, `--year 1999`, `--explicit`, `--quality 0..10`
(6–7 — если хотите качество выше, но помните про размер пака: ~1 МБ на минуту).

После импорта остаётся `python tools/check_project.py` и
`python tools/stage_pbo.py --clean --zip`.

### Если ffmpeg выдал «Header missing» / «Invalid data found when processing input»

Это **предупреждение ffmpeg о битом заголовке mp3**, а не ошибка импорта: музыка
из файла конвертируется, трек попадает в альбом. Так бывает у старых скачанных
mp3 и у файлов с «мусором» вместо ID3-тегов.

С версии `8149a86` импортёр сам глушит этот вывод и, если заголовок совсем
нечитаемый, повторяет попытку с ключом `-f mp3` (файл как raw-поток) — так
спасаются почти все такие файлы.

Ошибка — только если в отчёте появилась строка:

```
       ! НЕ СКОНВЕРТИРОВАН: Error opening input files: Invalid data found ...
```

Тогда файл действительно битый или это DRM-защищённая загрузка. Такой трек в
альбом не попадает: итог покажет `N file(s) could not be converted` и имя файла —
перекачайте его или пропустите.

## 3. Чего в паке быть не может

Только локальные `.ogg`. Интернет-радио (Icecast/Shoutcast, relay, куски эфира)
из проекта исключено: движок не умеет играть `http://`, а любая схема «эфира»
либо требовала софта у игроков, либо раздувала пак и требовала постоянной
пересборки. Разбор и код лежат в `_archive/internet_radio/` — если когда-нибудь
понадобится, вернёмся к нему отдельным решением.

## 4. Сборка пака

```bash
# 1. проверить, что все файлы на месте
python tools/generate_db_config.py --check

# 2. сгенерировать config.cpp + index.json
python tools/generate_db_config.py

# 3. подготовить staging и собрать PBO
python tools/stage_pbo.py --clean
BUILD_PBO.bat                  (Windows + DayZ Tools)
```

Генератор:

* проверяет существование каждого `.ogg`;
* проверяет, что файл действительно `.ogg`;
* берёт длительность из json или из `ffprobe`;
* пишет `CfgSoundShaders` и `CfgSoundSets` в маркеры `@@SHADERS_*@@` /
  `@@SOUNDSETS_*@@`;
* собирает `Music/index.json` (его читает игра);
* пишет отчёт в `build/report.txt`, включая список проблем.

Типичный вывод:

```
  @MusicRadioDB/Music/Rock/playlist.json: 12 entries
    ! 'rock_track_07': MISSING AUDIO Music/Rock/rock_track_07.ogg
  playable tracks : 11
  enabled         : 11
```

## 5. Обновление пака без боли

* **Добавили трек** → пересобрали PBO → обновили на сервере и в воркшопе.
  Сервер и клиенты обязаны иметь **один и тот же** индекс, иначе клиент увидит
  «Unknown track» (сервер прислал id, которого у клиента нет).
* **Удалили трек** → удалите и из json. Ссылки в сохранённых плейлистах на
  удалённый трек просто не сыграют, мод не падает.
* **Разбили на несколько PBO** (по жанрам) → у каждого свой `provider`
  (например `MusicRadioDB_Rock`), и все провайдеры перечисляются в
  `DatabaseConfig.json → providers`. Формула имени SoundSet учитывает provider,
  так что конфликтов не будет.
* **Версионирование**: держите `"version"` в индексе в соответствии с версией
  воркшоп-айтема, чтобы игроки видели, что пак устарел.

## 6. Проверка контракта

`python tools/check_project.py` сверяет `index.json` и `config.cpp`: у каждого
включённого трека должен быть `MR_<PROVIDER>_<ID>_SoundSet`, а файл — на месте.
Это ловит 90 % «почему не играет».

## 7. Лицензии

Музыка — ваша ответственность. Перед публикацией пака в Workshop:

* проверьте права на каждый трек (публичное исполнение / распространение);
* храните `CREDITS.txt` внутри пака со ссылками на источники и лицензии;
* не включайте чужие OST «просто потому что красиво» — это самая частая причина
  снятия мода с воркшопа.
