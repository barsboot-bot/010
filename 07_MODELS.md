# Модели (.p3d): кассета, MD-диск, плееры, карта памяти

Честная граница сразу: **`.p3d` — бинарный формат Bohemia (ODOL)**, его пишет
только Object Builder / Oxygen из DayZ Tools. Текстом или скриптом такой файл не
создаётся, поэтому «создать p3d» здесь можно только одним способом: подготовить
всё, что нужно *до* сохранения — геометрию, размеры, имена селекшенов, LOD-схему —
так, чтобы в Object Builder осталось импортировать и нажать Save.

Что уже готово в проекте:

```
Models/
├── src/*.obj  *.mtl      # меши в метрах, готовы к импорту
├── preview/*.svg         # чертёж в трёх проекциях с размерами
└── README.md             # таблица габаритов
```

Пересобрать: `python tools/make_models.py`.

## 1. Что за модели и какие размеры

Размеры взяты с реального железа — иначе предмет «не читается» в инвентаре и не
влезает в слот.

| Файл | Прототип | Габарит |
|------|----------|---------|
| `mr_minidisc.obj` | MD-картридж (Sony MDW-74) | 72 × 68 × 4 мм |
| `mr_cassette.obj` | компакт-кассета IEC I | 100 × 63.8 × 12 мм |
| `mr_mdplayer.obj` | портативный MD-плеер | 118 × 72 × 17 мм |
| `mr_cassettedeck.obj` | кассетный «walkman» | 140 × 110 × 35 мм |
| `mr_memorycard.obj` | SD-карта | 32 × 24 × 2.1 мм |

Каждая модель уже разбита на именованные группы (`shell`, `hub_left`,
`window`, `label`, `shutter`, `body`, `lid`, `screen`, `button_*`, `dial`,
`jack`) — в Object Builder это готовые named selections, по которым можно
назначать материалы и делать анимацию крышки.

## 2. Импорт в Object Builder

1. `File → Import → Wavefront (.obj)` → выбрать `Models/src/mr_cassette.obj`.
2. **Масштаб 1.0** — в файле уже метры (1 единица = 1 м), Object Builder тоже
   работает в метрах. Если импортировать с масштабом 0.001, получится предмет
   размером с пылинку — самая частая ошибка.
3. Проверить: `Structure → Bounding Center` показывает те же мм, что в
   `Models/preview/*.svg`.
4. Точка привязки (pivot) — **центр по X/Y, низ по Z** для предметов, которые
   лежат на земле; для диска/кассеты — просто центр.

## 3. LOD-схема (минимум, чтобы предмет жил в игре)

| LOD | Зачем | Что внутри |
|-----|-------|------------|
| `Resolution 0.000` | то, что видит игрок | вся геометрия, материалы |
| `View Geometry` | пулевые попадания по предмету | копия геометрии |
| `Geometry` | физика/коллизия | упрощённая коробка (2 треугольника на грань) |
| `Memory` | служебные точки | точки селекшенов (см. ниже) |
| `Shadow Volume 0.000` | тень | копия геометрии или отключить (`shadow = 0` в конфиге) |

В `Memory` LOD положить:

* `ce_center` — центр предмета (для инвентаря/эффектов);
* для плееров — точку `MR_MemCard` и `MR_Media` там, где физически вставляется
  карта и носитель (пригодится, когда захочется анимации).

Для кассеты и диска Memory-LOD достаточно, если не планируется анимация.

## 4. Материалы

OBJ приходит с MTL: `plastic`, `metal`, `label`, `glass`, `screen`, `button`.
В Object Builder это надо заменить на `.rvmat` (иначе модель будет белой).
**Готовые `.rvmat` уже есть** — `@MusicRadioDB/data/tex/*.rvmat`, по одному на
материал (`mr_cassette`, `mr_minidisc`, `mr_mdplayer`, `mr_cassettedeck`,
`mr_memorycard`, плюс тайловые `mr_plastic`, `mr_plastic_light`, `mr_metal`,
`mr_paper`, `mr_rubber`). Как они устроены и откуда взялись текстуры —
`docs/09_TEXTURES.md`.

```cpp
// в .p3d текстура называется mr_cassette, а материал ссылается так:
// MusicRadioDB\data\tex\mr_cassette.rvmat
```


Текстуры уже нарисованы: `Models/tex_src/*.png` (кассета 1024×512, MD 512×512,
плеер и дека 1024×512, карта 256×256). Осталось конвертировать PNG → `.paa`
через `DayZ Tools → TexView 2` — по шагам это расписано в
**`docs/09_TEXTURES.md`** (там же таблица форматов DXT и контактный лист).

## 5. Подключение модели к предмету

В `@MusicRadioCore/config.cpp` у класса заменить строку `model`:

```cpp
class MR_Cassette_Rock01 : MR_CassetteCase_Base
{
    scope = 2;
    displayName = "Cassette - Demo Rock A";
    model = "MusicRadioCore\data\mr_cassette.p3d";   // было: \DZ\gear\consumables\sewing_kit.p3d
};
```

Путь **без ведущего `\`** — это путь внутри PBO мода. Модель кладётся в
`@MusicRadioCore/data/`, а `stage_pbo.py` включает папку `data`, если её
добавить в список `include` в `tools/stage_pbo.py`.

## 6. Слот в машине: чтобы плеер было видно на торпеде

Слот `MR_DashSlot` объявлен в `CfgSlots` (`@MusicRadioCore/config.cpp`). Машины
заново **не объявляются**: в Enforce-конфиге нельзя дополнить чужой класс
(`class CivilianSedan : CarScript { ... }` даёт `/CfgVehicles.CivilianSedan:
Member already defined`), поэтому `attachments[] += ...` на ванильные машины не
делается. В слот можно положить кассету, мини-диск **или** плеер — играет то,
что положили (`MR_MediaItems.IsCarDockItem()` / `AlbumInVehicle()`), но **на
модели машины предмет не отображается**. Чтобы
отображался, нужны три вещи:

1. **Селекшен на модели машины.** В `.p3d` конкретной машины добавить селекшен
   с именем `MR_DashSlot` в месте торпеды. Это правка чужой (ванильной) модели —
   делается только в Object Builder и только для тех машин, которые вы реально
   хотите поддержать.
2. **Прокси в конфиге.** Готовый сниппет лежит в
   `Models/config_proxy_snippet.cpp` — там `CfgNonAIVehicles → ProxyMR_MediaPlayer`
   и поле `selection` в `CfgSlots → Slot_MR_DashSlot`. Подключать, когда модели
   плееров уже есть.
3. **Прокси-модель плеера** — та же `mr_mdplayer.p3d`, но с точкой привязки в
   центре и без лишних LOD'ов (только Resolution + Memory).

Что без этого работает уже сейчас: слот есть, вставить/вынуть кассету/плеер можно,
музыка с пристыкованной деки играет (`MR_MediaItems.AlbumInVehicle()`), в UI
показывается `docked deck: album 'rock01'`. Не видно только саму коробочку на
торпеде.

## 7. Слоты в рации

С 20261174 рация — полноценное устройство: у неё три слота, добавленных
конфигом (`CfgVehicles → PersonalRadio : Transmitter_Base`,
`attachments[] += { "MR_MemoryCard", "MR_Cassette", "MR_MiniDisc" }`), собранных
в группу инвентаря «Music media».

Почему повторён прямой парент `Transmitter_Base`, а не `PersonalRadio`:
`attachments[]` объявлен на уровне прямого родителя, а `+=` дописывает к нему;
объявление же `class PersonalRadio : ItemBase` даёт
`/CfgVehicles.PersonalRadio: Member already defined`. Это проверяет
`tools/selftest_no_keys_in_servermod.py → check_radio_slots()`.

Всё это **работает** — кассету/диск/карту можно вставить и вынуть, логика их
видит. Чтобы на модели рации появилось «окошко» под
на 3D-модели «окошко» под карту и кассету, нужно то же самое: селекшены
`MR_MemoryCard` / `MR_Cassette` / `MR_MiniDisc` на модели `PersonalRadio.p3d`
(ванильная модель, правится отдельно) + `selection` в `CfgSlots`.

Альтернатива без правки ванильных моделей: оставить слот «иконочным» (в
инвентаре слот виден, карта вставляется, но на 3D-модели углубления нет). Для
геймплея это ничего не меняет.

## 8. Чек-лист перед сборкой PBO

- [ ] модель импортирована с масштабом 1.0, габарит совпал с `Models/README.md`;
- [ ] есть LOD 0.000, Geometry, View Geometry, Memory;
- [ ] материалы заменены на `.rvmat` (не белая модель);
- [ ] `model = "MusicRadioCore\data\<файл>.p3d"` — без ведущего `\`;
- [ ] папка `data` добавлена в `include` в `tools/stage_pbo.py`;
- [ ] `python tools/check_project.py` — зелёный;
- [ ] `python tools/stage_pbo.py --clean` — `problems: 0`.

## 9. Частые ошибки

| Симптом | Причина |
|---------|---------|
| предмет размером с точку или с дом | импорт с неверным масштабом |
| модель белая/розовая | не заменили материал на `.rvmat` или не тот путь к `.paa` |
| предмет не появляется в инвентаре | нет LOD 0.000 или `scope = 0` |
| нельзя вставить кассету в плеер | `inventorySlot[]` предмета ≠ `attachments[]` плеера |
| слот есть, но пустой в UI | имя в `CfgSlots.name` не совпадает с `attachments[]` |
| пристыкованная дека не видна на машине | нет селекшена `MR_DashSlot` на модели машины / нет прокси |
