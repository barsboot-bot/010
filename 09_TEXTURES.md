# Текстуры накопителей: что сгенерировано и как превратить в `.paa`

Документ описывает **все текстуры носителей MusicRadio**: откуда они взялись,
что лежит в проекте и что нужно сделать на Windows, чтобы модели в игре
получили материал.

Коротко: **никаких скачанных картинок в проекте нет.** Стоковые фото кассет и
MiniDisc (Adobe Stock, Getty, Craiyon) отклонены — водяные знаки и лицензия
запрещают их распространение в моде. Вместо них все текстуры **нарисованы
процедурно** скриптом `tools/make_textures.py`, поэтому:

* лицензия чистая — файлы созданы для этого мода;
* результат воспроизводим (фиксированный seed `20261110`);
* правки — это правка скрипта, а не поиск новой картинки.

```

├── mr_cassette_co.png          # 1024x512  diffuse
├── mr_cassette_nohq.png        # normal
├── mr_cassette_smdi.png        # specular
├── mr_minidisc_*                # 512x512
├── mr_mdplayer_*                # 1024x512
├── mr_cassettedeck_*            # 1024x512
├── mr_memorycard_*              # 256x256
├── mr_plastic_*                 # 256x256  тайловый пластик (корпуса, бока)
├── mr_plastic_light_*           # 256x256  светлый пластик
├── mr_metal_*                   # 256x256  шлифованный металл
├── mr_paper_*                   # 256x256  бумага этикетки
└── mr_rubber_*                  # 256x256  резина / кнопки
@MusicRadioCore/data/tex/       # МАТЕРИАЛЫ МОДА (идут в PBO)
└── *.rvmat  (10 штук)          # ссылки на *.paa, см. раздел 4
Models/preview/textures_sheet.png  # контактный лист для быстрой проверки глазами
```

Всего 30 PNG (10 материалов × 3 карты). PNG индексные (256/128 цветов) — это
близко к тому, что всё равно даст DXT-сжатие в `.paa`, и держит папку в 1.8 МБ
вместо 8.8 МБ. **В PBO PNG не кладём**: движок их не читает, а вес растёт.

> `.rvmat` уже лежат в `@MusicRadioCore/data/tex/` и попадут в PBO при
> `tools/stage_pbo.py`. Пока рядом нет `.paa`, движок нарисует модель белой —
> это нормально до шага 3.

## 2. Персональные обложки альбомов (кассета и MD)

Кроме общих листов, скрипт рисует **свой комплект на каждый альбом** медиа-пака:
имя альбома и исполнитель печатаются прямо на этикетке.

```bash
python tools/make_textures.py --albums          # только альбомные обложки
python tools/make_textures.py                   # всё: общие листы + обложки
python tools/make_textures.py --album kostya --side B --shell red
python tools/make_textures.py --albums --dry-run   # показать, ничего не писать
```

Что получается на каждый альбом `albumId`:

| Файлы в `Models/tex_src/` | Что на картинке |
|---------------------------|-----------------|
| `mr_cassette_<albumId>_*.png` | кассета 1024×512: полоса `SIDE A`, `TYPE I · 46 MIN`, имя альбома (в одну или две строки, шрифт сам подбирается под ширину), исполнитель, окно с катушками |
| `mr_minidisc_<albumId>_*.png` | MD 512×512: синяя полоса `MD · 74 MIN`, имя альбома, исполнитель, шторка |

Материалы (`*.rvmat`) создаются рядом: `mr_cassette_kostya.rvmat`,
`mr_minidisc_kostya.rvmat`. Имя текстуры совпадает с именем в модели, поэтому
на один и тот же меш кассеты разные альбомы выглядят по-разному — это и есть
смысл персональных обложек.

Полезные ключи:

* `--side A|B` — что напечатано в углу кассеты;
* `--shell black|grey|red|blue|gold` — цвет корпуса кассеты (альбомы можно
  различать по цвету даже без чтения этикетки);
* `--minutes N` — переопределить `46 MIN` / `74 MIN` (по умолчанию физическая
  ёмкость носителя, а длительность пака видна в консоли при генерации).

Чекер предупреждает, если для альбома нет обложки:

```
! textures: album carrier art is missing for mr_cassette_kostya_co.png
  - run: python tools/make_textures.py --albums
```

Сгенерированные PNG лежат в `Models/tex_src/` (в PBO не идут), `.rvmat` — в
`@MusicRadioCore/data/tex/` и попадают в пак. Дальше — та же конвертация в
TexView 2, что и для остальных текстур.

выглядит каждая текстура, не открывая 30 файлов.

## 4. Три карты на материал

DayZ (как и Arma 3) использует схему `_co` / `_nohq` / `_smdi`:

| Суффикс | Назначение | Как получено | Формат в `.paa` |
|---------|------------|--------------|-----------------|
| `_co` | цвет (diffuse) | нарисовано скриптом | DXT1 (или DXT5, если нужна прозрачность) |
| `_nohq` | нормали (рельеф) | из размытой яркости `_co`, tangent space, **+Y вверх** | DXT5 |
| `_smdi` | блики (specular) | из сглаженной яркости `_co`: светлое и гладкое блестит сильнее | DXT1 |

Нормали специально **мягкие** (blur 2.5 px, strength 1.8): у кассеты и деки
рельеф — это фаски и утопленные окна, а не шум. Резкая карта нормалей в DXT5
превращается в «сыпь» и на моделях 10–15 см выглядит как брак.

## 5. `.rvmat`: как материал связывает карты

На каждый материал есть `.rvmat` в `@MusicRadioCore/data/tex/`, например
`mr_cassette.rvmat`. Он ссылается на `.paa` **по пути внутри PBO**:

```cpp
class Stage1 { texture = "MusicRadioCore\data\tex\mr_cassette_nohq.paa"; ... }; // нормали
class Stage2 { texture = "MusicRadioCore\data\tex\mr_cassette_co.paa";   ... }; // цвет
class Stage4 { texture = "MusicRadioCore\data\tex\mr_cassette_smdi.paa"; ... }; // блики
specularPower = 30;
```

`MusicRadioCore\` — это имя PBO (папка `@MusicRadioCore` без `@`), поэтому путь
не зависит от того, как мод назвали на сервере.

В Object Builder материал подключается к модели так (см. `Models/README.md`):

```cpp
class Textures
{
    class mr_cassette
    {
        // в .p3d: Texture name = "mr_cassette", а не путь к .paa
        // путь задаётся здесь:
        // selection = "mr_cassette";
        // material  = "MusicRadioCore\data\tex\mr_cassette.rvmat";
    };
};
```

Проще: в Object Builder в свойствах текстуры ставим **`*.rvmat`**, а не `.paa` —
тогда блики и нормали подхватятся автоматически.

## 6. Конвертация PNG → `.paa` в TexView 2 (пошагово)

`.paa` — бинарный формат, текстом его не создать, нужен **TexView 2** из
**DayZ Tools** (или Arma 3 Tools). Работа занимает 20–30 минут на все файлы.

### 6.1. Подготовка

0. **Библиотеки Python.** Генератору нужны `Pillow` и `numpy`:
   `python -m pip install pillow numpy` (это делает `REBUILD.bat`, шаг 0/4).
   Симптом, если их нет: `ModuleNotFoundError: No module named 'numpy'`.


1. Запустите Steam → **DayZ Tools** → **Установить** (если ещё не стоит).
2. Откройте папку проекта, в ней — `Models\tex_src\`. Там лежат PNG:
   по три карты на каждый материал (`_co`, `_nohq`, `_smdi`).
3. Убедитесь, что папка назначения существует:
   `@MusicRadioCore\data\tex\` (в ней уже лежат `.rvmat`).

### 6.2. Если TexView 2 пишет «Error loading file»

Такое было с первой версией исходников: PNG сохранялись **индексными**
(палитра 256 цветов) ради размера, а загрузчик TexView 2 (Qt `QImage`) палитровые
PNG не открывает. Сейчас все PNG — обычные **24-битные RGB**, и TexView их
читает.

Если ошибка всё равно появилась, порядок действий:

1. **Проверить, что файл на месте и не нулевой.** В окне TexView видно путь:
   `P:\mods\MusicRadio\Models\tex_src\mr_cassette_co.png`. Файл должен
   существовать и весить сотни килобайт.
2. **Проверить режим файла** (в PowerShell):

   ```powershell
   python -c "from PIL import Image; im=Image.open(r'Models\tex_src\mr_cassette_co.png'); print(im.mode, im.size)"
   ```

   Должно быть `RGB (1024, 512)`. Если `P` — файл старый, палитровый:
   пересоберите текстуры (`python tools\make_textures.py`).
3. **Взять TGA-версию.** Скрипт умеет писать рядом 24-битные TGA — формат,
   который TexView 2 и Object Builder понимают лучше всего:

   ```bat
   python tools\make_textures.py --tga
   ```

   Появятся `Models\tex_src\tga\*.tga` (по одному на каждую карту). В TexView 2
   открывайте их: `File → Open` → `mr_cassette_co.tga` → `Save As` → `PaC
   (DirectX)`. Занимают они много (~1.5 МБ на файл), поэтому пишутся только по
   запросу; в `.gitignore` они исключены.
4. **Открыть PNG в другом редакторе и пересохранить** как PNG 24-bit
   (Paint.NET, GIMP, Photoshop — «8 бит/канал, без палитры»).
5. **Обновить DayZ Tools** в Steam (ПКМ по DayZ Tools → Свойства → Обновления).
   Старые сборки TexView капризны к форматам.

### 6.3. Один файл: пошагово

1. **Пуск → TexView 2** (или `DayZ Tools → TexView 2`).
2. `File → Open…` → выберите `mr_cassette_co.png`.
3. В окне просмотра должна быть видна картинка. Если она чёрная — файл не
   прочитался, проверьте, что это тот самый PNG.
4. `File → Save As…`:
   * **Тип файла**: `PaC (DirectX)` — это и есть `.paa`;
   * **Имя**: `mr_cassette_co.paa` (суффикс `_co` сохраняем!);
   * **Папка**: `…\@MusicRadioCore\data\tex\`.
5. В диалоге сжатия:

   | Что конвертируем | Формат | Почему |
   |------------------|--------|--------|
   | `_co` (цвет) | **DXT1**, если нет прозрачности; **DXT5**, если есть альфа | 1 бит альфы у DXT1 хватает только для «вырезать/оставить» |
   | `_nohq` (нормали) | **DXT5** | нормалям нужна плавная альфа-канальная точность, DXT1 даёт ступеньки |
   | `_smdi` (блики) | **DXT1** | серая карта, цвет не нужен |

   Галочку **Generate mipmaps** оставляем включённой (иначе текстура «звенит»
   на расстоянии). `Compression quality` можно оставить по умолчанию.
6. Нажмите **OK**. В папке появится `mr_cassette_co.paa`.
7. Повторите для `mr_cassette_nohq.png` → `mr_cassette_nohq.paa` (DXT5) и
   `mr_cassette_smdi.png` → `mr_cassette_smdi.paa` (DXT1).

### 6.4. Все 36 файлов: ускорение

Полный список — это 12 материалов × 3 карты (10 общих + обложки альбомов).
Варианты, от быстрого к ручному:

**A. Пакетный режим TexView 2.** В окне есть `File → Batch Convert…` (в разных
версиях Tools пункт называется `Convert multiple files`): выбираете сразу все
`*.png` из `Models\tex_src`, задаёте формат и папку вывода — программа
обработает очередь сама. Формат выбирается один на запуск, поэтому удобно
сделать три прохода: все `*_co.png` (DXT1), все `*_nohq.png` (DXT5), все
`*_smdi.png` (DXT1).

**B. Командная строка** (ключи зависят от версии Tools — проверьте на одном
файле, прежде чем гнать пачкой):

```bat
for %F in (Models\tex_src\*_co.png) do TexView2.exe -i "%F" -o "@MusicRadioCore\data\tex\%~nF.paa"
```

**C. Руками**, как в 6.2 — 36 раз. Дольше, но надёжнее всего, если версия
Tools нестандартная.

### 6.5. Проверка после конвертации

В `@MusicRadioCore\data\tex\` должно быть:

* **36 файлов `.paa`** — ровно столько же, сколько PNG в `Models\tex_src\`;
* **12 файлов `.rvmat`**;
* **ни одного `.png`** (PNG в пак не идут — движок их не читает).

Быстрая проверка из консоли проекта:

```bat
dir /b @MusicRadioCore\data\tex\*.paa | find /c ".paa"
python tools\check_project.py
```

Чекер покажет `textures: 12 rvmat, 36 .paa ready` вместо `0 .paa yet`.

## 7. Что уже прописано в коде

Три уровня, все три уже готовы:

**1. Материал (`*.rvmat`)** — `@MusicRadioCore/data/tex/<материал>.rvmat`, по
одному на каждый материал: `mr_cassette_<albumId>`, `mr_minidisc_<albumId>`,
`mr_plastic`, `mr_metal`, `mr_paper`… Внутри — ссылки на `_nohq`, `_co`, `_smdi`.

**2. Класс предмета (`config.cpp`)** — у каждой кассеты и каждого MD есть
привязка материала, её пишет генератор:

```cpp
class MR_Cassette_Kostya : MR_CassetteCase_Base
{
    scope = 2;
    displayName = "Cassette - Kostya (Костя)";
    descriptionShort = "Side A: Kostya, ~340 min. Insert into a cassette player.";
    hiddenSelections[] = { "mr_cassette" };
    hiddenSelectionsMaterials[] = { "MusicRadioCore\\data\\tex\\mr_cassette_kostya.rvmat" };
};
```

* `hiddenSelections[]` — список «селекшенов» модели, материал которых можно
  подменять из конфига. Имя `mr_cassette` / `mr_minidisc` — это имя группы
  полигонов **внутри `.p3d`**, а не путь к файлу;
* `hiddenSelectionsMaterials[]` — каким `.rvmat` этот селекшен заменить. Именно
  здесь альбом и получает свою обложку: один и тот же `.p3d` у всех кассет,
  разный материал — разная этикетка.

Те же строки продублированы в базовых классах (`MR_CassetteCase_Base`,
`MR_MiniDisc_Base`) — чтобы селекшен существовал, даже если моделей пока нет.

**3. Модель (`.p3d`)** — то, что нужно сделать в Object Builder:
селекшен `mr_cassette` (грани корпуса и этикетки) и на нём материал
`MusicRadioCore\\data\\tex\\mr_cassette_<albumId>.rvmat`. Подробный порядок —
`docs/07_MODELS.md`, раздел 4.

### 7.1. Слоты и иконки

* Слоты (`MR_Cassette`, `MR_MiniDisc`, `MR_DashSlot`) от текстуры **не
  зависят**: у них `ghostIcon = "missing"` — это заглушка. Нормальные иконки
  слотов — отдельные `.paa` 64×64 (рисуются из тех же обложек, задача на потом).
* Иконка в инвентаре (`iconTexture`) у предметов пока ванильная, потому что
  модель ванильная. Когда появится свой `.p3d` — иконку можно отрендерить из
  него прямо в Object Builder (`Export → Icon`).

## 9. Частые проблемы

| Симптом | Причина | Что делать |
|---------|---------|------------|
| модель белая | нет `.paa`, `.rvmat` не подключён или неверный путь | проверить, что в `data/tex` есть `.paa`, а `hiddenSelectionsMaterials` указывает на существующий `.rvmat` |
| модель розовая/в клетку | в `.rvmat` указан несуществующий `.paa` | TexView сохранил файл с другим именем (например, `mr_cassette_co.PAA` в другом регистре) |
| текстура есть, но «плоская» | не сконвертированы `_nohq` или `_smdi` | конвертировать все три карты, проверить строки `Stage1`/`Stage4` в `.rvmat` |
| все альбомы выглядят одинаково | `hiddenSelectionsMaterials` не сработал | проверить, что имя селекшена в модели ровно `mr_cassette`, а в конфиге класс-наследник не перекрыт |
| надпись на этикетке «поплыла» | длинное название | перерисовать: скрипт сам уменьшает шрифт, но если не помогло — `--album <id>` и правка `two_lines()` |
| кириллица квадратами | шрифт | скрипт использует DejaVu Sans (кириллица есть); если в системе его нет — положить `DejaVuSans-Bold.ttf` рядом со скриптом |
| TexView пишет «Error loading file» | палитровый PNG или битый файл | пересобрать текстуры (`python tools\make_textures.py`), при повторе — TGA-версии (`--tga`) или пересохранить PNG в 24-bit RGB, см. 6.2 |

## 10. Как переделать текстуру

```bash
# правим функции draw_* в tools/make_textures.py, затем:
python tools/make_textures.py        # перезапишет 30 PNG и контактный лист
```

Скрипт детерминированный: одинаковый код → одинаковые картинки. Менять seed
имеет смысл только для тайловых материалов (там шум), у пяти носителей
рисунок задан координатами.
